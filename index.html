Terminal Commands

How to navigate and do things in the Terminal
Type these commands and hit "Enter"

pwd             # Print Working Directory: "Where am I right now?"
ls              # List: "What files and folders are in here?"
cd foldername   # Go down into a specific folder (child folder). Often follows 'ls'
cd ..           # Change Directory: Go up one level (parent folder)
open .          # Mac ONLY: Open your current Working Directory in Finder
start .         # Windows ONLY: Open your current Working Directory in Explorer
ctrl + c        # Cancel/Quit: Stop a running process (Same on Mac/Windows/Linux)
clear           # Clean: Clear the terminal screen so you have a blank slate

Basic Git Commands (That you will use again and again!)

Git is your Version Control system. It tracks the history of your creativity & allows you to update your webpages online.
Type these commands and hit "Enter"

Note: The # indicates a comment (an explanation). Do NOT type the # or any text after it into the terminal! 

git clone             # Download a project from GitHub
git log               # View history (Enter = scroll through more items, 'q' = exit)
git status            # See what has changed since the last save
git add .             # Stage all changes to be saved
git commit -m 'msg'   # Save the changes with a label
git push              # Upload your saves to GitHub
q                     # Quit: Use this to get out of 'git log' or stuck screens

The Development Loop (Save/Commit/Push)

This is the cycle you will repeat every time you work. Think of it as: Create/Modify → Save → Record (commit) → Upload (push).

  1. Modify: Make changes to your index.html (add text, new elements, images, etc.).
  2. Save: Press Cmd + S (Mac) or Ctrl + S (Windows) in your code editor.
  3. Record & Upload: Run these commands in your terminal:
git add .                  # Tell git to pay attention to your new changes
git commit -m 'message'    # Store your changes locally with a descriptive label (replace 'message' with your own)
git push                   # Upload your changes to GitHub
  1. Verify: Go to your browser and refresh your .github.io page.

Pro-Tip: It can take 30–60 seconds for GitHub to process your "push." If you don't see your changes immediately, wait a minute and refresh again!

View Your Sites Locally (Testing Before Pushing)

You don't have to git push just to see if your code is working. We use a local server to preview changes after you save your files.

The "Live Server" Extension (Recommended)

Installing

  1. In VS Code, click the Extensions icon (the 4 squares on the left sidebar).
  2. Search for "Live Server" (the one by Ritwick Dey) and click Install.

Use:

  1. Open your index.html file so you can see your code.
  2. Look at the very bottom-right of your VS Code window and click the "Go Live" button.
    (If you don't see it, right-click your index.html and select "Open with Live Server").
  3. Your page will open automatically in your web browser. Keep this tab open while you work!
  4. The Test: Make a small change to your code and Save (Cmd/Ctrl + S). Watch your browser—it should refresh with your change instantly.

IMPORTANT: Your browser will only update AFTER you press Cmd+S / Ctrl+S to save your work!

Which URL am I looking at?

  • Local (Starts with 127.0.0.1): This is your private workspace. Changes show up here after you Save.
  • Global (Starts with github.io): This is your public site. Changes show up here only after you Push.

Pro-Tip: If you see a white dot on your file tab in VS Code, it means you haven't saved. Save the file, and your Live Server browser tab will refresh automatically!

Creating a Repo, Cloning, First Commit, Making A Github Page

Follow these steps whenever you begin a new assignment (A1–A5) to ensure your repository is set up correctly.

Phase 1: Create the Repo on GitHub

  • Create a new repo: If Assignment 1, name it a1-git-labyrinth. (For future assignments, follow the same pattern: a2-name, a3-name, etc.).
  • Settings: Ensure it is Public and check the box to add a README. Click "Create repository."
  • Get the Link: On the repo's main page, click the green "<> Code" button and copy the URL.

Phase 2: Bring it to your Computer

  1. Open VS Code and go to File > New Window.
  2. Click "Clone Git Repository..." on the start screen (or in the Source Control tab).
  3. Paste the URL at the top and hit Enter. Pick a folder on your computer to save it in.
  4. Click "Open" when the notification pops up.

Phase 3: The First Commit

  1. Make a new index.html file in your new project folder.
  2. Go to the HTML Boilerplate section of this page and copy the code.
  3. Paste that code into your index.html and save.
  4. Run through the Basic Development Loop (Add, Commit, Push) to make sure your connection is working.

Phase 4: Making it Live (GitHub Pages)

Your assignment won't have a URL until you turn this on for each new repo:

  1. On GitHub.com, go to the Settings tab of your repository.
  2. On the left sidebar, click Pages.
  3. Under Build and deployment > Branch, change "None" to main.
  4. Click Save.

*Note: Ensure you are in the Settings for your repository (top of the page), not your personal GitHub profile settings!

Success! You are now ready to start working on the creative requirements listed in the syllabus.

Branches & Merges

Working on "branches" lets you experiment without breaking the main site.

Important Note on your Webpage: GitHub Pages is set to show your main branch (some older repos might call this master). Think of this as your Live Stage. Other branches are your Behind-the-Scenes or Rehearsal Spaces and their code will never be displayed on the actual website! 

    git checkout -b name      # Create a new branch & jump into it
git push -u origin name   # Tell GitHub this new branch exists
git branch                # List all branches (* = where you are)
git checkout main         # Switch back to the LIVE webpage version
git merge source          # Bring changes from a branch into your current branch (blends them)
git log --all --decorate --oneline --graph –pretty    # Visualize your branches

Time Travel (Viewing AND Playing with Earlier Versions)

Did you break something and want to go back? Or do you just miss an old design? Here is how you travel back in time and start over from there.

  1. Find your destination:

    Type git log --oneline to see your save history. Copy the 7-character code (the "hash") next to the version you want.

  2. Peeking vs. Staying:

    To just peek at the past: git checkout <hash>

    To stay and start a new experiment from that spot: git checkout -b <new-branch-name> <hash>

  3. Share your experiment:

    After making this branch, push it to GitHub so that Michael (your instructor) can see it when grading:

    git push -u origin <new-branch-name>
  4. Build the Future:

    In this new branch, you can experiment with new ideas BUILDING on top of your earlier idea. Go ahead and get creative! Just remember to:
    git add .
    git commit -m '...'
    git push
    ...frequently to save your progress!

  5. Switching back to your latest work:

    If you want to leave the past and go back to your most recent work on a specific branch:

    git branch            # List all your available "timelines" (branches)
git checkout main     # Go back to your primary live site
git checkout name     # Jump to any other specific experiment branch

Assignment 1: Labyrinth Techniques

To build a labyrinth, you need to branch from places other than main or develop.

Strategy: Always check git branch before you start a new one to see "where you are standing." 

git checkout feature-a     # Jump onto an existing experiment
git checkout -b feature-b  # Create a NEW branch STARTING from feature-a
git merge feature-c        # Blend feature-c into your current branch

Linking your Versions

You need to link to 5 specific "significant versions" on your homepage. Here is how you find those URLs on GitHub:

  • Go to your a1-git-labyrinth repo on GitHub.com.
  • Click on "Commits".
  • Click the <> icon (Browse Files) next to a specific commit.
  • Copy that URL from your browser address bar.
  • In your username.github.io index.html, use this code:
<a href="PASTE_URL_HERE">Version 1: "the name of your version"</a>
<p>Annotation: In this version, I experimented with...</p>

Michael's Tip: Make sure the URL goes inside the double quotes "". The text between the > and </a> is what becomes the clickable blue link text in the web page itself!

Resolving Common Git Errors (Dont't Panic!)

If the terminal gives you a scary error message, look here first.

1. "Everything is gone!" (Detached Head)

If you checked out a commit hash and your new work isn't showing up, you are likely in "Detached HEAD" state. It just means you aren't standing on a branch.

git checkout main    # Jump back to safety

2. "Everything is red!" (Merge Conflicts)

Git found two different versions of the same line and needs you to pick a winner. In VS Code, look for these buttons above the red text:

  • Accept Current Change: Keeps the work on your computer (the version you were just typing).
  • Accept Incoming Change: Keeps the work coming from elsewhere (GitHub or the other branch).
  • Accept Both Changes: Keeps both so you can combine them manually.

Which one? If you want your new work to stay, pick Current. If you like the other version better, pick Incoming. If you pick the wrong one, press Cmd/Ctrl + Z immediately!

3. "Rejected / Non-fast-forward"

This usually happens when GitHub has work that your computer doesn't have yet (like if you edited a file directly on Github.com/your-repo).

git pull origin main   # Pull the cloud changes down to your computer

Michael's Rule: If you're stuck for more than 15 minutes, stop and ask a classmate or post a screenshot to Brightspace. Don't delete your folder and start over!
