Terminal Commands

How to navigate in the Terminal. Type these commands and hit "Enter"

pwd             # Print Working Directory: "Where am I right now?"
ls              # List: "What files and folders are in here?"
cd foldername   # Go down into a specific folder
cd ..           # Go up one level (parent folder)
open .          # Mac ONLY: Open current folder in Finder
start .         # Windows ONLY: Open current folder in Explorer
ctrl + c        # Cancel/Quit: Stop a running process
clear           # Clear the terminal screen

Basic Git Commands

Git is your version control system. Type these commands and hit "Enter"

Note: The # is a comment. Do NOT type it into the terminal!

git clone             # Download a project from GitHub
git log               # View history ('q' = exit)
git status            # See what has changed since the last save
git add .             # Stage all changes to be saved
git commit -m 'msg'   # Save the changes with a label
git push              # Upload your saves to GitHub

The Development Loop (Save / Commit / Push)

  1. Modify: Make changes to your index.html.
  2. Save: Press Cmd+S (Mac) or Ctrl+S (Windows).
  3. Record & Upload:
git add .
git commit -m 'describe what you changed'
git push
  1. Verify: Refresh your .github.io page in the browser.

Pro-Tip: It can take 30–60 seconds for GitHub to process your push. If you don't see changes, wait a minute and refresh.

Branches & Merges

Working on branches lets you experiment without breaking the main site.

Important: GitHub Pages shows your main branch — the Live Stage. Other branches are your rehearsal spaces and won't appear on the public site.

git checkout -b name      # Create a new branch & jump into it
git push -u origin name   # Tell GitHub this branch exists
git branch                # List all branches (* = where you are)
git checkout main         # Switch back to the live branch
git merge source          # Bring changes from another branch in

  </head>
  <body>

    <!-- Your visible content goes here -->

  </body>
</html>

Writing Great Commit Messages

Structural changes

git commit -m "Add unordered list for childhood bedroom inventory"
git commit -m "Wrap emotional register text in a blockquote"

Experimental changes

git commit -m "Experiment: nesting 10 levels of div to create a tunnel"
git commit -m "Branching off nostalgia to try a more hostile tone"

Merges

git commit -m "Merge glitchy-text into nostalgia branch"
git commit -m "Resolve conflict in floorplan; kept the distorted version"

Michael's Rule: Avoid messages like "update" or "fixed." Will you know which version of the labyrinth you're stepping into in three days?

Resolving Common Git Errors

1. Detached HEAD

You checked out a commit hash and are no longer on a branch.

git checkout main    # Jump back to safety

2. Merge Conflicts (everything is red)

Git found two different versions of the same line. In VS Code, use the buttons above the red text: Accept Current, Accept Incoming, or Accept Both.

3. Rejected / Non-fast-forward

GitHub has changes your computer doesn't have yet.

git pull origin main   # Pull cloud changes down first

Michael's Rule: If you're stuck for more than 15 minutes, ask a classmate or post a screenshot to Brightspace. Don't delete your folder and start over!
